# 権限の説明（ストア審査用）

申請のたびに書き直さないための定型文。該当節をストアのフォームへ貼る。

## 必須の権限

| 権限 | 用途 |
|---|---|
| `storage` | プロバイダ設定と取得済みスナップショットをブラウザ内だけに保存する |
| `tabs` | 登録済み usage ページを開いているタブを探す。更新時に開く |
| `scripting` | ユーザーがアクセスを許可した usage ページにローカル読み取り処理を注入する |
| `https://raw.githubusercontent.com/ishizakahiroshi/*` への host access | URL だけのサンプル台帳を取得する。**Try samples** でユーザーが同意した後にのみ実行する |

## 任意（optional）の権限

| 権限 | 用途 | 要求するタイミング |
|---|---|---|
| host access（`*://*/*`） | ユーザーが登録した usage ページを読む | プロバイダの追加・保存時 |
| `contextualIdentities`（Firefox のみ） | コンテナ一覧を取得し、アカウント枠をコンテナに紐づける | 設定でコンテナ機能を有効にしたときだけ |
| `cookies`（Firefox のみ） | `tabs.create` に `cookieStoreId` を渡すために Firefox が要求する。指定したコンテナで usage ページを開くため | 同上 |

### `contextualIdentities` / `cookies` の補足

ブラウザプロファイルはサイトごとに 1 セッションしか保持しないため、同じ AI サービスに 2 アカウントを持つユーザーは常に一方しか見られない。両方のセッションを同時に成立させられるのは Firefox のコンテナだけなので、各アカウントの usage ページをユーザーが指定したコンテナで開く。

- Cookie の値は読み書きも送信もしない。`cookies` が要るのは、Firefox が `tabs.create` の `cookieStoreId` 引数をこの権限で保護しているためだけ。
- どちらも optional で、ユーザーがコンテナ機能を明示的に有効にしたときにのみ要求する。拒否しても拡張は従来どおり動作し、その場合はブラウザ側でアカウントを切り替えて 1 つずつ更新する。
- Chrome ビルドではこれらの権限を宣言しない（Chrome にコンテナ API は存在しない）。

## 複数アカウントの識別データ

取得値をどの枠に書くか判定するため、ユーザーは「アカウントを表す文字」（メールアドレスや表示名）の位置を教えられる。拡張はその要素の selector/fingerprint と、文字の SHA-256 ハッシュ（インストールごとのランダム salt 付き）だけを保存する。文字そのものは保存せず、ログにも出さず、ブラウザ外へも出さない。
